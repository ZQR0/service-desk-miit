# TODO-лист команды: сервис-деск и каталог услуг для преподавателей

Многомодульный монолит (Maven), Spring Boot, PostgreSQL, Keycloak. Подробности архитектуры, правил модулей и Docker описаны в `service-desk-guide.md`.

## Команда и зоны ответственности

| Кто | Модуль / зона | Главное |
|---|---|---|
| Дима, Никитос | `catalog` | каталог услуг и шаблоны чек-листов |
| Леха, Арсений | `notifications` | уведомления, SSE в браузер |
| Олеся, Аня | `requests` | заявки, согласование, статусы, чек-листы, история, статистика SLA |

## Общий порядок работы

Работа идёт в четыре фазы. Внутри фаз подкоманды работают параллельно, не дожидаясь друг друга: чужие модули подменяются заглушками их публичных интерфейсов (профиль `stub`, Mockito в тестах).

| Фаза | Что происходит | Кто |
|---|---|---|
| **0. Основа** | каркас проекта, Docker, Keycloak, CI, схема БД, согласование контрактов | Ярослав делает, все ревьюят контракты |
| **1. Разработка модулей** | каждая подкоманда реализует свой модуль на заглушках соседей | подкоманды параллельно, Ярослав делает `auth` и общий код |
| **2. Интеграция** | заглушки заменяются реальными модулями, сквозные сценарии | все вместе, ведёт Ярослав |
| **3. Стабилизация и сдача** | баги, производительность, документация, демо | все |

### Кто кому что должен (критические зависимости)

## Общие правила для всех

- Правки чужого модуля идут только через pull request с ревью владельца (`CODEOWNERS`).
- Публичные интерфейсы, DTO и события меняются только по согласию всех потребителей; в описании pull request перечисляйте, кого это затрагивает.
- К `internal` чужого модуля не обращаемся, между сущностями разных модулей нет связей JPA и JOIN, наружу отдаём только DTO.
- Небольшие pull request лучше крупных, основная ветка всегда собирается и запускается.
- Каждый pull request проходит CI: сборка, тесты, архитектурная проверка.
- В репозиторий не коммитим секреты, `.env` остаётся локальным.
- Заглушки соседних модулей лежат в профиле `stub` и убираются при интеграции.
